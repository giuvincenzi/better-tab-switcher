# Languages (i18n)

The languages are English (`en`), Italiano (`it`), Français (`fr`), Español (`es`), Deutsch (`de`), Português (`pt-BR`),
Română (`ro`), Shqip (`sq`), Русский (`ru`), العربية (`ar`), 中文 (`zh-Hans`), 日本語 (`ja`) and 한국어 (`ko`). The
extension and the website's home page (`site/home/<code>.json`, `discoverability.md`) are translated; the user guide is
in English.

## The language in use

- Settings › **Language**: "Use browser language" (the default) or a language.
- With "Use browser language" the texts' language is Chrome's display language when translated, its parent too,
  Portuguese gives pt-BR, otherwise English; numbers and dates use the language's usual format.
- Chrome itself shows the extension's name, description and shortcut names in its own language, from
  `_locales/<code>/messages.json`. Everything the extension shows itself is in the language of the setting, read by the
  extension from the same files: `chrome.i18n` follows only Chrome's language, and Chrome has no Albanian display
  language.

## Texts

- **How texts are written.** Every text the user reads (labels, notes, errors, tooltips, dialogs) is a natural sentence,
  the way a person would say it: what happened and what the user can do next. No pieces glued with colons, no
  shorthand, no internal names. Short where space is short, but still a sentence.
- **Every translation, wherever the project has one (the extension, the home page, any other translated text), says what
  the English means the way a native speaker would say it, never word for word.** Before using a phrase, check on the
  internet that in that language it really conveys that concept: how native sites, Google and extensions of the same kind
  say it. When the literal sentence sounds unnatural, build it again (another order, another verb, two sentences),
  keeping the placeholders, the Chrome terms and the global words. The home page uses the extension's own words for its
  features, settings and keys (`_locales/<code>/messages.json`) and writes numbers and units as the extension does in
  that language. Avoid forms that would need the gender or number of a placeholder or of an item kind the sentence does
  not know.
- **No text for the user in code or markup.** `_locales/en/messages.json` holds the English texts;
  `_locales/<code>/messages.json` the translations.
- Keys: `Area_Name`. A sentence with values is **one key with placeholders**, never pieces glued together: word order
  changes between languages. An enum shown to the user maps each value to a key. Lists join with the language's list
  format. Each key's `description` says what each placeholder is.
- **Counts**: one key per plural form (`Key_one`, `Key_other`…). Each language has its CLDR forms.
- Numbers and dates for the user: the language in use; in stored data: language-independent, so the data is the same on
  every PC whatever its language.
- **Global words: never translated.** Some words are the same in every language: names, brands, terms the user wants
  kept as they are.
  - Which words are global is the user's decision: when a word looks global (a name, an acronym, a brand, a term
    written the same way in many languages), **ask the user** before treating it as global or translating it. Do not
    list them in the rules: the code holds them.
  - A label that is only a global word is only in `_locales/en/messages.json` (its `description` starts with "GLOBAL")
    and in the unit tests' list of global keys; no translation has it, so every language shows the same text, and the
    unit tests fail if a translation adds it.
  - Inside translated sentences a global word is written exactly as it is, never translated or transliterated.
- Not translated: data (titles and addresses of the tabs), keys written on the keyboard in shortcut lists.
- **Every new or changed text is translated into every language in the same pull request** (checked by the unit tests).
- Translations follow the terms Chrome uses in that language (its settings and pages). When a term is uncertain, look it
  up (Chrome in that language) instead of guessing.
- A new language: its line in the code's list of languages, its `_locales/<code>/messages.json`, its plural forms; for
  the home page its `site/home/<code>.json`, its line in `scripts/site.mjs` and its flag in `site/assets/flags`
  (`discoverability.md`).

## Right to left

- Arabic runs right to left (`dir` from the language in use, on every page and on the switcher). What stays left to
  right: key names and key caps, addresses, numbers in fields.
